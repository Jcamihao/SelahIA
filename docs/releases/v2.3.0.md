# Release Notes - v2.3.0 (Selah IA)

Confiabilidade do provider Gemini e cobertura de testes dos adapters.

## 🛡️ Retry no Gemini
- `GeminiProvider` repete em `429`, `500`, `502`, `503`, `504` e erros de rede (`ECONNRESET`, `ETIMEDOUT`, `EAI_AGAIN`, `EPIPE`, `ECONNABORTED`), com backoff exponencial e jitter.
- Respeita `Retry-After`; se o pedido for maior que `GEMINI_RETRY_MAX_DELAY_MS`, falha sem repetir. Erros `4xx` (exceto `429`) nunca são repetidos.
- `GEMINI_TIMEOUT_MS` agora é o **orçamento total por chamada**: o timeout de cada tentativa é o tempo que sobrou, então retries não estendem o pior caso além dos 45s anteriores.
- Novas variáveis: `GEMINI_MAX_RETRIES` (2), `GEMINI_RETRY_BASE_MS` (800), `GEMINI_RETRY_MAX_DELAY_MS` (8000).

## 🐛 Correção
- **Consolidação e Louvor devolviam `true` em vez do resultado.** Os validators de `consolidation-ai.schemas.ts` e `worship-ai.schemas.ts` eram type guards booleanos, mas os providers usam o retorno de `validate` como `data`. As 4 rotas (`sentiment-analysis`, `playbook`, setlist e notas de ensaio) respondiam `true` e aceitavam payload inválido sem erro. Agora retornam o dado ou lançam erro, como os demais adapters.

## ✅ Testes
- Suíte de 2 para **63 testes / 8 suites**: `provider-selection`, retry do Gemini, Consolidação, Louvor, Relatórios de culto, Kids (8 métodos, 8 validators, prompts) e receipt-parser do Lumen.
- Cada prompt tem teste com exemplo fixo, travando o conteúdo específico de cada app.
- `/coverage` adicionado ao `.gitignore`.

## ⚠️ Conhecido e não tratado
- O adapter de Louvor não confere se o `songId` devolvido existe no repertório enviado.
- O receipt-parser diz "Ollama retornou um JSON invalido" mesmo com Gemini ativo.
